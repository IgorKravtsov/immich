# Locked Albums — спецификация

Ветка: `feat/hidden-albums`. Делается для собственного форка (не апстрим).

## Цель

Расширить существующий Locked Folder (PIN-защищённое пространство, `AssetVisibility.Locked`) так, чтобы:

- в нём можно было держать **несколько альбомов** (locked-альбомы) и отдельные фото;
- locked-альбомами можно было **делиться** с пользователями, по ссылке с паролем и выборочно с партнёрами;
- всё синхронизировалось между устройствами и работало **в вебе и в мобильном приложении** (полный паритет).

## Решения

### Модель
- **D1. Одно защищённое пространство.** Используется существующий Locked Folder: тот же PIN, та же elevated-сессия (`session.pinExpiresAt`), тот же `visibility=locked` для отдельных фото. Отдельного второго пространства нет.
- **D2. Флаг альбома.** В таблице `album` появляется колонка `isLocked boolean not null default false`.
- **D3. Инвариант «фото в locked-альбоме ⇒ фото locked».**
  - Фото может лежать в нескольких locked-альбомах. Одновременно в locked- и обычном альбоме оно лежать не может.
  - Добавление фото в locked-альбом: фото становится `locked` и удаляется из всех обычных альбомов.
  - Пометка альбома как locked: все фото альбома становятся `locked` и удаляются из обычных альбомов.
  - Перевод отдельного фото в `locked` (как сейчас): фото удаляется из обычных альбомов. Из locked-альбомов **не** удаляется.
  - Перевод фото из `locked` обратно в `timeline` или `archive`: фото удаляется из всех locked-альбомов.
  - Добавить `locked`-фото в обычный альбом нельзя.
- **D4. Снятие пометки locked с альбома.** Только владелец альбома. Фото владельца альбома, которые лежат только в этом locked-альбоме, становятся `timeline`. Фото владельца, которые лежат и в других locked-альбомах, остаются `locked` и удаляются из этого альбома. Фото других участников удаляются из альбома и у них остаются `locked`. Переход происходит после подтверждения в UI.
- **D5. Редактор shared locked-альбома добавляет свои фото.** Эти фото становятся `locked` в его библиотеке и удаляются из его обычных альбомов. В UI перед этим показывается предупреждение.
- **D6. Загрузка в locked-альбом.** Если на мобильном бэкап связан с locked-альбомом, фото загружаются сразу с `visibility=locked`.

### Доступ
- **D7. PIN.** Чтобы читать locked-альбом, его фото, его активность и списки locked-альбомов, нужна elevated-сессия. Это касается и владельца, и получателей. У получателя без PIN в UI показывается подсказка «установите PIN».
- **D8. Где видно.** Locked-альбомы скрыты из `/albums`, «Shared with me / Sharing», поиска, памятей и карты. Список альбомов возвращает их только при явном запросе `isLocked=true` и elevated-сессии. В диалоге «Добавить в альбом» locked-альбомы показываются только при elevated-сессии и помечены замком.
- **D9. Шаринг пользователям.** Обычный шаринг альбомов работает для locked-альбомов. Получатель видит альбом только в своём Locked Folder, за своим PIN.
- **D10. Публичные shared links.**
  - Ссылку на locked-альбом можно создать только с паролем. Убрать пароль у такой ссылки нельзя.
  - Когда альбом помечается locked, ссылки без пароля на него удаляются.
  - Ссылки на отдельные locked-фото тоже требуют пароль.
- **D11. Партнёры.**
  - Locked-контент по умолчанию партнёрам не виден.
  - Владелец явно разрешает конкретному партнёру видеть конкретный locked-альбом или конкретное locked-фото: таблица `partner_locked_access(sharedById, sharedWithId, albumId | assetId)`.
  - Партнёр видит разрешённое только в своём Locked Folder, за своим PIN.
  - Обычный (не locked) контент партнёры видят как раньше.
- **D12. Активность.** Комментарии и лайки в locked-альбомах разрешены. Доступны только при elevated-сессии.
- **D13. Уведомления.** Для locked-альбомов уведомления, email и push идут нейтральным текстом, без названия альбома и превью.

### UI
- **D14. Веб.**
  - Страница Locked Folder получает вкладки «Фото | Альбомы».
  - Меню альбома: «Переместить в Locked Folder» и «Убрать из Locked Folder» (с подтверждением и пояснением D4).
  - Locked-альбом открывается по своему маршруту внутри Locked Folder и требует PIN.
  - Модалка шаринга работает как обычно и показывает пометку о блокировке. Для публичной ссылки пароль обязателен.
  - Партнёры: в модалке шаринга locked-альбома секция «Партнёры» с чекбоксами. В меню locked-фото пункт «Показать партнёрам…».
- **D15. Мобильный.** Полный паритет с вебом: вкладка «Альбомы» в Locked Folder, lock/unlock в меню альбома, настройки партнёров, пометка замком в выборе альбомов для бэкапа.
- **D16. Защита на устройстве.** PIN или биометрия и таймаут как сейчас. Кэш thumbnails как сейчас, без дополнительного шифрования.

### Синхронизация
- **D17.** Флаг `isLocked` передаётся в sync stream (`AlbumV2`, новая версия `AlbumV3` или расширение `AlbumV2`). Мобильный клиент хранит флаг в локальной БД и фильтрует по нему локально. Разрешения для партнёров тоже передаются в sync stream, чтобы партнёр получал разрешённые locked-фото.

## Фазы
1. Сервер: схема, инвариант D3/D4/D5, ослабление запретов Locked Folder для альбомов, фильтры, доступ (D7, D8), загрузка с `locked`.
2. Веб: locked-альбомы (D8, D14).
3. Шаринг locked-альбомов: пользователям, по ссылке с паролем, уведомления (D9, D10, D13).
4. Разрешения для партнёров: сервер и веб (D11).
5. Мобильный: sync stream, локальная БД, UI, бэкап (D15–D17).

## Технические решения (реализация)

- **Партнёр + locked-альбом.** Разрешение партнёру видеть locked-альбом реализовано как обычный шаринг альбома этому партнёру с ролью `viewer`. Так альбом автоматически синхронизируется на мобильный, а доступ и списки работают без новой логики. В UI это отдельная секция «Партнёры» с чекбоксами в модалке шаринга locked-альбома: чекбокс добавляет или удаляет партнёра как viewer.
- **Партнёр + отдельное locked-фото.** Таблица `partner_locked_asset(sharedById, sharedWithId, assetId)` с аудитом для sync. При удалении партнёрства и при выводе фото из `locked` строки удаляются.
- **Locked Folder получателя:**
  - «Фото» — свои locked-фото плюс locked-фото партнёров, которые явно разрешены. Сервер: `GET /timeline/buckets?visibility=locked&withPartners=true`.
  - «Альбомы» — `GET /albums?isLocked=true`: свои и расшаренные locked-альбомы.
- **Миграция** `1795218798796-AddLockedAlbums`.

## API-контракт

- `AlbumResponseDto.isLocked: boolean` (обязательное).
- `CreateAlbumDto.isLocked?: boolean`: создать сразу locked. Нужна elevated-сессия. Переданные `assetIds` становятся `locked` (D3).
- `UpdateAlbumDto.isLocked?: boolean`: lock/unlock. Только владелец, нужна elevated-сессия. Семантика D3/D4.
- `GET /albums?isLocked=true`: только locked-альбомы (свои и расшаренные), нужна elevated-сессия. Без параметра или с `false` locked-альбомы не возвращаются. `?assetId=` тоже не возвращает locked-альбомы без elevated-сессии.
- `PUT /albums/{id}/assets`, `PUT /albums/assets`: в locked-альбом можно добавлять свои фото (обычные или locked). Обычные фото при этом становятся `locked` и удаляются из обычных альбомов. Нужна elevated-сессия. Добавить `locked`-фото в обычный альбом нельзя: ответ `no_permission`.
- `GET /timeline/buckets` и `GET /timeline/bucket` с `albumId` locked-альбома требуют `visibility=locked` и elevated-сессию. `visibility=locked&withPartners=true` разрешён.
- Shared links:
  - создание ссылки на locked-альбом или на locked-фото без `password` → 400;
  - убрать пароль у такой ссылки → 400;
  - при lock альбома ссылки на него без пароля удаляются.
- `GET /partners/{id}/locked-assets` → `{ assetIds }`. `PUT` и `DELETE /partners/{id}/locked-assets` с телом `{ assetIds }`. Везде `{id}` — пользователь, с которым я делюсь, и нужна elevated-сессия.
- Загрузка: `POST /assets` с `visibility=locked` (поле уже есть в `AssetMediaCreateDto`).
- Sync:
  - `SyncAlbumV2.isLocked: boolean`;
  - новый `SyncRequestType.PartnerLockedAssetsV1` → `SyncEntityType.PartnerLockedAssetV1 {sharedById, sharedWithId, assetId}` и `PartnerLockedAssetDeleteV1`.
  - Партнёрские ассеты, включая locked, уже приходят через `PartnerAssetsV2`. Locked-ассеты чужих shared-альбомов приходят через `AlbumAssetsV2`.
